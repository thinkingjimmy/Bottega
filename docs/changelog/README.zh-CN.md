- **跨设备对话保持一致。** 桌面与 Web 共用对话呈现、输入区控件和已读状态。阅读 Chat 后，执行电脑与其他已连接界面同步清除未读状态。问题与 Plan 确认期间保留停止操作，排队命令保留恢复入口；同步期间产生的回复在恢复后继续保留。
- **发送前选择 Project 分支。** 桌面与 Web 的 New Chat 支持搜索、切换和新建分支；远程操作在所选电脑执行。进入项目设置再返回时，完整草稿、附件、引用、Plan、权限与模型选择保留。项目忙碌或 Git 冲突时，先处理问题再切换。
- **设置与控件对齐。** Web 与桌面的 Agent 选择、侧栏控件和设置布局保持一致；Skills 空列表采用与扩展相同的页面框架。插件安装通过桌面完成；介绍页可返回插件列表，工具设置包含插件与托管 Preview 控件。

本次 Cloud Sync 升至**协议 15**。使用云功能的每台桌面都需要升级；旧协议 14 客户端更新后才能重新连接。已有云端内容、同步密码和账号密钥保留。完全退出 Bottega 后手动替换应用。本次 Apple 芯片 macOS 预发布使用 ad-hoc 签名、未经 Apple 公证，不进入 GitHub Latest。见[升级说明](../getting-started/README.zh-CN.md#升级到-022)。

## 2026-10-04 — v0.2.0

**macOS Apple 芯片 + Web。** [下载 0.2.0](https://github.com/thinkingjimmy/Bottega/releases/tag/v0.2.0)，或打开 [Bottega Web](https://app.getbottega.app)。本次为手动更新的预发布版本。Apple Developer 资格仍在审核中，macOS 安装包使用 ad-hoc 签名，尚未公证。Windows、Linux 与 Android 发行另行安排。

### 新增与改进

- **插件集中管理。** 设置 › 插件 › 所有插件 展示能力、依赖、来源与使用情况；已开启且有设置的插件在左侧单列。Base、Provider、Workflow、草图、Memory 与 Dock 共用一致的管理入口，关闭插件保留内容并说明受影响的功能。
- **Agent 配置与流程。** 模型与推理强度改为下拉选择，加载失败保留修改并提供重试。Skills、MCP 工具与流程读取 Memory 均有明确选择。已安装 CLI 通过能力检查后，Codex、Claude Code、Kimi Code 与 OpenCode 都能执行流程步骤；规划与评审始终只读。
- **可编辑的草图插件。** 草图同时保留图片与可编辑源内容，支持版本切换；构建失败保留原可用版本。已确认的草图可在重启后恢复，版本更新也保留已打开画布里的未保存内容。
- **Memory 控制可见。** Memory 仍默认关闭。Web 设置可以请求拥有者电脑暂停或恢复，并显示实际生效状态。流程读取 Memory 需要单独授权，保持只读，不采集新记忆。
- **Dock 放到指定屏幕。** 可使用主屏、优先外接屏或指定显示器，并在左侧、底部或右侧停靠。位置仅保存在本机，已有布局可同步。本次预发布支持与系统程序坞共存，并在可用时使用原生玻璃外观；暂不提供替代模式。
- **Web 工作台补齐。** App 与 Base 菜单适应窄屏，离线操作说明当前状态，运行详情展示完整步骤报告与证据。App 开关保留数据并确认影响范围；受支持的浏览器可选择开启通知。静态与 Base 型 App 继续支持浏览器，server 型 App 界面仍限桌面使用。
- **恢复流程更明确。** 文件夹恢复与启动失败给出具体操作；退出前等待草稿确认保存；设置加载失败保留当前列表与草稿，支持重试。App 或插件编译中断后可正常重新启动，组件更新保留本地作者修改；刷新导入历史可修正 Project 归属，并保留已保存的 Chat。

### 升级与使用范围

生产后端与 Web 已使用**协议 14**。需要云端功能的电脑请更新到 0.2.0，旧协议 13 的桌面必须升级后才能重新连接。本次保留已有云端内容与同步密码。安装前请完全退出 Bottega，并备份内容与应用数据目录，见[升级与安装说明](../getting-started/README.zh-CN.md#升级到-020)。

从 Release 页面下载 DMG 或 ZIP 及 `release-manifest.json`，对安装包运行 `shasum -a 256`，将输出与清单中对应安装包的 `sha256` 手动比较。本次预发布不安装自动更新，也不进入 GitHub Latest。第三方 Provider 模块、公开插件市场与公开 SDK 发行不在本次开放范围。详细实机走查将继续进行，后续修复计划通过 0.2.x 交付。

## 2026-09-30 — v0.1.9

**升级前：** 请备份 Bottega 文件夹与应用数据目录。0.1.9 不会打开 0.1.8 的 Chat 数据库：旧库原样留存，对话索引从你的 Bottega 文件夹重建。云端服务在这次发布时已重置，0.1.9 之前上传的内容不再保留：请重新登录，第一台登录的电脑重新设定同步密码。同步协议升到 13，0.1.8 的桌面已无法同步。见[升级说明](../getting-started/README.zh-CN.md#升级到-019)。

### 新增与改进

- **流程：Plan · Develop · Review。** 为 Project 的 Base 开启内置流程，指定由哪个 Agent 配置负责规划、开发和评审。从某一行开始运行：你先确认计划，再对结果选择接受、带例外接受或返工。Base 会新增「阶段」与「验收标准」两列；运行可以按步骤暂停、取消或重试，等你处理的运行会提醒你，满 24 小时自动暂停。本版本中可以担任流程步骤的是 Claude 与 Codex。
- **Agent 配置。** 设置 › Agent 配置 保存可复用的配置——Provider、模型、指令、权限、只读或可写的工作区以及网络——可从空白、规划、开发或评审起步。配置随账号同步，修改只影响保存之后开始的运行。
- **插件与 App。** 设置里集中列出已安装的内容：Base、四个 Provider、Workflow 插件、你安装的扩展，以及各 Agent 自带的插件。关闭插件不会删除任何内容。
- **在 Web 与手机上处理「等你处理」。** 在 [app.getbottega.app](https://app.getbottega.app) 可以开始运行、确认、决定、返工、暂停或取消；「等你处理」铃铛列出所有等你决定的事项。静态与 Base 型 App 的界面现在也能在浏览器里打开，并提供「使用 Chat」「编辑」与构建状态。
- **随包 Node 运行时。** Bottega 自己的工具——内置 MCP server、App 界面编译器、Agent 适配器以及 App 的 Node 脚本——运行在应用内置的 Node 24 上，不再使用 PATH 里的 Node。
- **更严格的 Agent 边界。** Agent 回合不再能读取 GitHub CLI 的配置目录；评审计划永远不会提升 Agent 的权限；浏览器工具只读取本 Chat 的标签页和你选中的那一个；Codex 在逐项询问、代我批准与 Plan 模式下改为在 Bottega 的沙箱里执行命令。
- **对话更稳。** 草稿在退出、崩溃或重启后仍在；Chat 不在屏幕上时，排队消息照常发送；Bottega 还在启动时发出的消息会等待并自动发送；文件快照失败时提供「重试」或「跳过」，不再锁住输入框。
- **登录确认改为选验证码。** 在浏览器里批准桌面登录时，需要选中那台电脑上 Bottega 显示的验证码。
- **其他变化。** 设置 › Lab 及其中的 Keep Agent connections 开关已移除。Development Kanban 不再随包提供，已安装的副本照常可用。Bottega 文件夹丢失时会打开恢复对话框，可以定位文件夹或改用新文件夹。
- **协议 13。** 同步协议现在承载 Agent 配置、流程列，以及流程运行和其中的「等你处理」事项。

### 下载与安装

这个版本**只提供 Apple 芯片的 macOS 版本**：DMG 与 ZIP。Windows 与 Linux 安装包会在之后的版本恢复，在此之前这两个平台上的安装停留在 0.1.8。这个构建**未签名、未公证**。

**macOS（Apple 芯片）：** 打开 DMG，把 Bottega 拖入「应用程序」。未签名下载需要在终端一次性移除该应用的隔离标记，然后再打开：

```bash
xattr -rd com.apple.quarantine /Applications/Bottega.app
```

开始对话前，请先安装并登录至少一个受支持的本机 CLI。0.1.0 或 0.1.1 用户需要手动安装 0.1.9，因为旧版本仍有此前的更新器问题。

## 2026-09-24 — v0.1.8

**升级前：** 无需任何准备。0.1.8 原样打开 0.1.7 的 Chat 数据库、设置与 Bottega 文件夹，云端数据也保留。同步协议升到 10，同一账号下的每台电脑都应更新：0.1.7 的桌面会被要求先更新才能继续同步。见[升级说明](../getting-started/README.zh-CN.md#升级到-018)。

### 新增与改进

- **Bottega Dock（macOS 15 及以上，Apple 芯片）。** 一条程序坞，放你在 Bottega 里做的 App、其它应用、访达、下载、废纸篓，以及每个 Agent 一个 AI 额度环。它可以停在系统程序坞上方与之并存，也可以替代它：此时 Bottega 把系统程序坞设为自动隐藏，并在后台项目里加一个小的恢复项，Bottega 意外停止时由它恢复系统程序坞。在 设置 › Dock 里开启；**恢复系统程序坞** 始终可用——在设置里、在 Dock 的右键菜单里，也在 Bottega 的菜单栏菜单里。
- **Dock 布局跟随账号。** Dock 布局端到端加密，在你的各台电脑之间同步。两台电脑同时修改时，Bottega 能合并的自动合并，其余的询问你。
- **设置处处同一种写法。** Dock、同步与 Memory 页改用与其它设置页相同的分组与列表行；错误与进度就显示在所属的那一行，分步设置统一在同一种弹窗里完成。引导页换成左侧步骤栏的新布局。
- **移动 Bottega 文件夹。** 设置 › 通用 里的 **移动文件夹** 会在 Bottega 重启时移动文件夹，所有保存的路径随之更新。移到另一块磁盘时会先完整复制并核对，旧副本随后移入废纸篓。
- **清空所有数据。** 设置 › 通用 › 危险操作 里的 **清空这台电脑上的所有数据** 会删除这台电脑上的对话、设置、密钥与登录状态，并重新从引导开始；也可以同时把 Bottega 文件夹移入废纸篓。云端数据保留，再次登录后会回来。
- **Bottega 文件夹被删除后重新进入引导**，不再停在恢复对话框；已无法打开的对话副本会移入文件夹的 `.trash`，只提示一次。
- **协议 10。** 同步协议前进一步，承载加密的 Dock 布局。本地数据不变。

## 2026-09-23 — v0.1.7

**升级前：** 无需任何准备。0.1.7 原样打开 0.1.6 的 Chat 数据库与设置，云端数据也保留。同步协议升到 9，同一账号下的每台电脑都应更新：0.1.6 的桌面会被要求先更新才能继续同步。已有的同步密码照常可用。见[升级说明](../getting-started/README.zh-CN.md#升级到-017)。

### 新增与改进

- **设置：Providers、Updates、Community。** Providers 决定新 Chat 默认使用的 Agent，以及所有 Agent 选择器里的排列顺序。Updates 把 Bottega 与每个已安装的 Provider CLI 及其版本列在一起，可逐行更新，也可 **全部更新**——先更新各 Provider，最后更新 Bottega，因为它会重启。Community 保留 GitHub、问题反馈与发布说明链接。原来的 About 与 Backends 页面已移除；安装与登录 Agent 仍在 Agent 设置流程里。
- **Agent 暂时接不住的插话不再失败。** Agent 工作时你发出的消息，若它支持插话就在当前这一轮使用；若不支持（Kimi Code 与 OpenCode），消息会被保留，本轮一结束就发出；从另一台设备发出时，回执会写明「将在本轮结束后发送」。只有 Agent 完全无法接受的输入才会被拒绝，草稿保留。若本轮已经结束，被拒的插话会提供 **作为新消息发送**。
- **远程附件发出前先清理。** 发往另一台电脑时——无论从 Cloud Web 还是从驱动远端 Chat 的桌面——照片最长边缩到 2048 px，相机元数据（位置、设备、EXIF / XMP）、GIF 注释块等内嵌元数据都会被移除；文件按真实格式校验。浏览器能读取的 HEIC 照片会自动转换，读不了时给出明确说明。已上传但 20 小时未发送的附件会提示重新上传，而不是在发送时失败；Cloud Web 也不再把自己刚上传的文件从云端下载回来显示。
- **更强的同步密码。** 新设定的同步密码至少 12 个字符，包含字母与数字，至少 5 个不同字符，不能以大段重复或连续字符为主，不能包含邮箱名、`bottega` 或最常见的密码。表单会随输入逐条打勾。已有的密码照常解锁。
- **离线的电脑会说离线了多久。** 没醒着的电脑会显示「休眠」「离线」或「断网」以及距上次在线的时间，直接显示在输入框里。
- **协议 9。** 同步协议前进一步，承载新的插话结果，并为即将到来的手机 App 准备服务端。本地数据不变。

### 新增与改进

- **一条对话属于创建它的那台电脑。** Bottega 不再把运行中的对话在电脑之间搬来搬去。本地就是本地，远程就是远程：你打开持有这份工作的电脑，然后在任何地方操作它。执行者选择、交接与跨电脑队列一并退役，它们过去向你提出的问题也一起消失。
- **登录即远程操作。** 一台登录的电脑会发布自己的侧栏——它的 Project 与 Chat——并接受针对它们的命令。产品里没有第二个开关：设置的同步一栏只有登录状态、本机显示名和退出登录。首次设置不再询问「只在这台电脑上使用还是连接账号」，所有人都从本地开始，登录是之后的步骤。同步密码仍然在登录流程里：第一台电脑设定，之后的每台电脑、浏览器与手机输入。
- **在侧栏里切换电脑。** Cloud Web、手机浏览器与桌面共用侧栏顶部的一条电脑切换器，一台电脑一个标签，醒着时带小圆点，离线时显示「离线 · 5 分钟前」。账号里出现第二台电脑后才出现，桌面永远把自己排在第一位。电脑可在设置里改名；新电脑注册时撞名会自动变成「…（2）」。账号下还没有任何电脑时，浏览器会被告知先在一台电脑上登录，而不会被要求输入一个它无法设定的密码。
- **使用另一台电脑的 Project。** 远端 Project 带地球角标与归属电脑名，不提供目录、路径或「选择文件夹」——它在这里本来就没有目录。在它下面新建的 Chat 会在那台电脑上创建、执行与存储。桌面侧栏 Projects 分组的 `+` 现在提供**本地 Project** 或 **钉住远端 Project…**：钉住只是把另一台电脑的 Project 放进本机侧栏，不复制任何内容；取消钉住对拥有者毫无影响；拥有者删除或归档后，该行仍在并标注状态，菜单里只剩「取消钉住」。
- **电脑离线不再挡住你的修改。** 改名、归档、调整顺序、编辑 Base 行、写 App 记录在拥有它们的电脑睡着时照常工作，等它醒来后对账。需要它醒着的只有执行类动作——发送、停止、批准、回答、插话、删除 Chat——这些控件就地置灰并说明原因，而不是把草稿一起收走，电脑回来后自行恢复。两个设备同时回答同一个权限请求时，第二个得到的是一行「已在 *电脑* 处理」，而不是一个错误。
- **一个 Bottega 文件夹属于一台电脑。** 第一次同步会记录归属，既记在账号里，也写进文件夹。同一台电脑在重装、清空数据或换 profile 后零操作接管；另一台电脑被指名拒绝，并用一句话说明该怎么做。从未同步过的文件夹在任何电脑上都能打开。一台电脑已发布的内容，无论它是否醒着，都能在浏览器和你的其他电脑上读取。
- **导入的对话在哪里都能继续。** 导入的 Codex、Claude Code 或 Kimi 历史，在全新档案里、从文件夹重建的工作区里、或 Project 尚未选择目录时，都不再变成只读。它用普通输入框打开，转录里只有一条分隔线标出导入历史的结束点。
- **首次上传说真话，也更短。** 设置 › Sync 现在按真实上传字节计数，不再停在 `0 B`，并且正好停在自己的总量上；小的对话先传，几秒内数字就开始走。每条消息的网络往返约减少一半。
- **协议 8。** 同步协议与本机 Chat 数据库同时前进，没有兼容层，这也是上面那段升级说明的由来。

## 2026-09-02 — v0.1.0

- 发布首批安装包。Bottega 现在可以从 GitHub Releases 获取 macOS arm64 DMG 与 ZIP、Windows x64 NSIS 安装包，以及 Linux x64 AppImage，全部由本次 tag 对应的提交构建。这批产物未签名，首次启动时各平台需要的一次性操作见[快速开始](../getting-started/README.zh-CN.md)。

- 让长对话的打开成本恒定。时间线、Chat 大纲与 Chat 内查找全部分页：打开一个有几万 turn 的 Chat 与打开一个短 Chat 代价相同，向上回溯也不会重新加载整份转录。

- 收窄 fact 写入。一个 turn 只更新它真正拥有的 fact，并发 turn、Memory 交付与 Base 写入不再互相覆盖状态。
- 关闭合并评审发现的问题。App Use 只在收到 completed 回执后才导航，被拒绝或恢复中的 App 不会再移动窗口；撤销 App 的 Base 访问权限成为一次原子操作，访问权与生命周期不再出现半状态；App 与 Project 的固定、Project 外观与设置导航重新组织，侧边栏始终反映真正打开的内容。
