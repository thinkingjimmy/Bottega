# Bottega 功能

[文档首页](../README.zh-CN.md) · [English](./README.md)

Bottega 把 Agent 对话视为一个可持续、本地工作空间的控制面。产品由以下核心能力域构成。

## Multi-agent

- 通过统一、后端无关的 ACP transport 连接 Codex、Claude Code、Kimi Code 与 OpenCode。
- 聊天空闲时可为下一轮切换 Agent，保留同一转录、每条回复的作者及有界历史接续；各家官方 CLI 继续管理自己的登录、用量与配额。
- 输入框展示运行时与认证可用性，并提供有作用域的安装、登录和重试入口。
- 在设置页和 Agent 选择器查看 Codex、Claude Code、Kimi 与 OpenCode Go 可获得的配额窗口、剩余额度及重置时间，覆盖滚动、每周与每月三种周期。
- 后台标题生成指定一个明确的 Agent 与模型；四家均可选择，不可用的项说明原因而不是从列表中消失。
- 提供 Plan、运行中 Steer、消息队列与可见的工具过程，同时不掩盖不同后端的能力差异。
- 创建 Section 与 Subagent 并行工作，查看进度，在明确预算内交接上下文，并把有价值的结果提升为持久 Section。
- 搜索和接续受支持的本机 CLI 历史，不静默改写原始记录。
- 导入的历史在任何档案中都能用普通输入框继续，Project 是否已绑定目录都不影响；转录里只有一条分隔线标出导入历史的结束点。

## 草图

- 通过输入框 **+ → 草图** 绘画、添加文字或八种图形，并局部擦除笔迹或图形。
- 自适应方形画布提供浮动工具、撤销/重做、颜色与粗细控制。
- 从草稿或还原队列中重新打开草图继续编辑，发送时通过普通图片附件流程交付白底 PNG。
- 草图作为内置插件管理，可通过 Agent 对话修改副本、切换已保存的版本。构建失败时保留原可用版本，已确认的草图源内容可在重启后恢复。

## 产物

- Agent 的可视化直接在转录中内联渲染，可展开，也可在 Chat 右栏打开。
- 对一轮产出的文件提供预览、保存、在文件夹中显示与快速查看；工作表可在明确的行合并确认后导入 Base。
- Claude 的 artifact 在内置浏览器中打开，复用既有的持久浏览器分区。
- 预览始终沙箱隔离：产物框架不获得网络或存储权限；超限、中断或格式无效的产物说明原因而不是继续渲染。
- 其他电脑产出的产物在该电脑同步完成后可读，在此之前显示明确的等待状态。

## Base

- 让 Chat 或 Project 在对话旁拥有结构化、以 row 为事实源的数据空间。
- 同一份数据支持 Table、List、Kanban、Map、Chart 与 Gallery 六种视图。
- 支持公式、relation、筛选、排序、附件、行历史，以及 CSV/JSON/XLSX 交换。
- Agent 通过显式内置工具与 revision 校验读取和修改 Base。
- App 写入受 capability 约束，GUI 不会静默获得无限制数据权限。

## 流程

- 为 Project 的 Base 开启内置的 **Plan · Develop · Review** 流程：在 Base 的 ⋯ 菜单中选择**设置流程…**，或在 Project 设置 › 流程 中添加。指定由哪个 Agent 配置负责规划、开发和评审；计划由你确认，结果由你决定。
- Base 会新增锁定的**阶段**列（规划、开发、评审、完成）和**验收标准**列，空间足够时再加一个**看板 · 按阶段**视图。你原有的列不会被改动。
- 在某一行点 ▶ **运行流程** 开始运行。先接受计划或结束运行；之后对结果选择接受、带例外接受（需填写理由）、返工（保留计划或重新规划），或结束。
- 可以暂停、继续、取消或强制停止运行，重试某一步，或对结果未知的步骤核对结果，也能打开任意一步背后的 Chat。等你处理的运行会在开始等待时和第 23 小时各提醒一次，满 24 小时自动暂停。
- 规划与评审始终在只读工作区里运行。Codex、Claude Code、Kimi Code 与 OpenCode 在已安装 CLI 通过能力检查后均可担任流程步骤；不可用的配置留在列表中说明原因，CLI 版本变化后会重新检查。
- 修改配置或流程，只影响之后开始的运行。

## Agent 配置

- 在 设置 › Agent 配置 中保存可复用的配置：从空白、规划、开发或评审起步，选择 Provider 与模型，填写指令与用途，并设置权限（逐项询问、代我批准或完全访问）、工作区（可以修改文件或只读）与网络。
- 配置可以用于所有 Project，也可以只用于部分 Project。
- 模型与推理强度使用与输入框相同的下拉选项；加载失败可以重试，同时保留列表和未保存修改。
- 选择 Skills 与 MCP 工具，查看运行实际获得的范围；规划与评审保持只读限制，不使用外部 MCP 工具。
- 单独决定流程是否可以读取长期 Memory；流程运行不会采集新记忆。
- 配置随账号同步；保存后的修改只影响之后开始的运行。

## 插件

- 在 设置 › 插件 › 所有插件 中浏览卡片，查看各插件的能力、依赖、来源与使用情况。已开启且有设置的插件在左侧单列；App 保留在独立的应用页。
- Base（始终开启）、四个内置 Provider、Workflow、草图、Memory 与 Dock 通过统一插件设置管理。关闭插件保留已有内容与设置，受影响的功能会说明缺少的依赖。
- 安装符合要求的插件包前，先查看来源、权限与签名，再在拥有该插件的电脑上确认；卸载插件包与删除保留数据是两个独立选择。
- 本版本未开放第三方 Provider 模块，生产环境仍提供四个内置 Provider；不包含公开插件市场或 SDK 发行。

## App

- 从不可变 Git revision 安装 static、server 或 Base-backed App。
- 随包的记账、健身和设计画布均使用 React 界面与共享交互规范。
- 安装、重建、授权与激活前检查 App 的最低 Bottega 版本，升级后返回原候选继续确认；三个随包 App 均要求 Bottega 0.1.3 或更新版本。
- App 改名保留当前运行版本、数据与授权，无需重新构建。
- 可从桌面或 Web 关闭、重新打开 App。关闭前说明将停止的运行工作，保留排队任务，Base 数据仍可编辑；破坏性操作单独确认。
- 使用随包交付的 Bottega Design Canvas 创建自包含 HTML 方向、比较 Live/History 版本，并把编号视觉锚点送回 Agent；预览不获得网络或存储权限。
- 使用随包交付的 Fitness Log 浏览 17 个肌肉区域的 72 个动作、查看动作动图并管理训练计划，宿主 React 界面支持五语言。
- 通过 App SDK 读取完整、版本一致的 Base 快照，并获得可恢复的加载状态和显式重试入口。
- 把 App 绑定到 Chat 与 Project，同时分离使用、编辑和授权。
- 通过受约束的产品 SDK，在结构化数据旁呈现 App GUI。
- 针对精确 App generation，分别授权 read、insert、patch、delete 与 attachment 能力。

## 工具与 Extension

- Settings › Tools 提供全局默认值，并允许针对一个精确 Project 覆盖内置工具与手动 MCP server。
- turn 开始前冻结最终工具与 MCP plan，重试和 session 恢复不会静默采用更新后的权限。
- Extension 可安装到全局或一个精确 Project；Skill、App requirement、session、retained data 与删除清理共用同一 scoped owner。
- MCP 密钥只进入 main-owned sealed storage；持久化所有权证据不完整时一律 fail closed。

## Memory

- 长期 Memory 默认关闭，召回或采集前必须获得明确同意。
- 可选择产品托管的本机 OpenViking 或 EverOS 后端。
- 召回范围可以限定为单个 Chat、一个 Project group，或个人工作空间。
- 在把上下文交给 Agent 前，严格分离可信产品指令与不可信召回事实。
- 明确显示交付、重建、来源、版本与注意状态，不把“不可用”伪装成“空”。
- 可在 Web 设置中暂停或恢复某台电脑的 Memory；离线请求保持待执行，直到该电脑实际应用。
- 记忆库保存在本机，但提取内容可能调用你配置的模型服务并产生费用。回填既有历史需要独立同意；普通采集暂停后，已单独授权的重建仍可能继续。

## 后台活动

- 后台运行由一个开关管理，登录自启可单独设置，两项默认关闭。
- macOS 可选择 Bottega Logo 图标、黑白菜单栏图标或刘海任务面板。系统记住选择，没有连接刘海屏时使用图标；Windows/Linux 使用系统托盘。
- 从刘海面板关注运行中的任务和待处理请求，支持键盘导航，并可返回相关聊天。
- 通过可用的后台入口重新打开或退出 Bottega。

## Bottega Dock

- 在 macOS 15 及以上的 Apple 芯片电脑上，把你在 Bottega 里做的 App、其它应用、访达、下载、废纸篓与每个 Agent 的 AI 额度环放进同一条程序坞。
- 在 设置 › 插件 › Dock 中开启。0.2.0 支持与系统程序坞共存，本次预发布不提供替代系统程序坞的模式。
- 可使用主屏、优先外接屏或指定显示器，并停靠在左侧、底部或右侧；显示器和边缘偏好仅保存在这台电脑上。
- 支持时使用原生玻璃外观，不可用时回退到稳定背景；关闭插件保留布局。
- 同一账号的每台电脑使用同一份端到端加密的 Dock 布局；同时修改会自动合并，真正的冲突会询问你。

## Cloud Sync

- 同步始终可选：不登录也能完整使用，首次设置里不会提到账号；登录本身不上传任何内容，直到你确认第一次同步。
- 通过系统默认浏览器完成 Google 登录，在浏览器里选中那台电脑上 Bottega 显示的验证码来批准请求，桌面应用再接续会话；Bottega 不会索取该密码。
- 用独立的同步密码解锁已同步内容。新设定的密码至少 12 个字符，包含字母与数字，至少 5 个不同字符，不能以大段重复或连续字符为主，不能包含邮箱名、`bottega` 或最常见的密码；表单会随输入逐条打勾。内容密钥在你自己的设备上用 Argon2id 派生，内容在上传前用 XChaCha20-Poly1305 封装。
- 明确接受没有找回：没有恢复密钥、没有其他设备批准、没有密码重置，也没有重置同步。创建加密空间前会说明该风险并要求确认。
- 一个账号一个加密空间。第一台电脑设定同步密码，之后的每台电脑、浏览器与手机输入它；只有桌面能设定。
- 设置的同步一栏只有三件事：登录状态、本机显示名、退出登录。退出登录只停止发布与接受命令，不删除任何内容；清除这台电脑的云端副本是另一个动作，删除账号又是另一个。
- 首次上传诚实可见：同步行按真实上传字节计数，且小的对话先传，几秒内数字就开始走。
- 同步 Chat 及其工具过程、Subagent 与附件，Base 及其 App 记录，Project 元数据与 Skills。冲突的修改保留双方候选并交由显式决定，不静默覆盖。
- 离线或暂停时继续工作：本机内容保持可读，排队任务按同一身份恢复；密码错误或网络中断都不会删除本地数据或云端密钥。

## Cloud Web 与远程操作

- 在 [app.getbottega.app](https://app.getbottega.app) 的浏览器中阅读 Chat，转录、工具过程、Subagent 与附件与桌面一致。
- 搜索聊天标题及最近 7 天的消息正文。搜索在浏览器中针对解密后的内容运行，查询词与明文索引不上传。
- 使用同样的六种 Base 视图，读取和编辑已同步的 App 记录，恢复或删除归档项目，并管理设备、会话与偏好。
- 跟进 Project Base 上的流程运行：开始运行、确认计划、决定结果、返工、暂停、继续、取消或重试某一步。**等你处理**铃铛列出所有等你决定的事项，可从运行查看完整步骤报告与证据。流程和 Agent 配置仍在桌面设置；需要电脑确认的插件请求由该电脑处理。
- 可在信任的浏览器上保持解锁，也可随时重新锁定。静态与 Base 型 App 的界面也能在浏览器里打开；server 型 App 的界面、应用内浏览器和本机工具仍属于各自的电脑。
- 支持手机浏览器：768px 以下的布局、触控目标、抽屉与拖拽交互自适应；App 与 Base 菜单适应窄屏，离线状态在受影响的操作旁显示。
- 浏览器支持时可选择开启通知；实际送达取决于浏览器、系统权限与设备状态。
- 登录即远程操作：一台登录的电脑把自己的 Project 与 Chat 发布到账号并接受命令，产品里没有第二个开关。
- 用侧栏顶部的电脑切换器切换电脑，Cloud Web、手机与桌面共用同一个组件。账号里出现第二台电脑后才显示，标签带在线状态，桌面把自己排在第一位；切换器下方的侧栏属于被选中的那台电脑。
- 在设置里给本机改名；与其他电脑重名会被拒绝，新电脑注册时撞名会自动加数字后缀。
- 被选中的电脑醒着时即可操作：发送消息、查看实时输出、停止、批准或拒绝权限请求、回答追问、插话与追加消息。目标必须在线、已解锁且协议版本一致。
- 多个设备可以操作同一条 Chat：消息按到达顺序排队，重复的停止只算一次，对同一个权限请求的第二次回答显示一行「已在 *电脑* 处理」而不是错误。
- 使用另一台电脑的 Project：它带地球角标与归属电脑名，不提供目录与路径，在它下面新建的 Chat 在那台电脑上创建、执行与存储。桌面可以把它钉进本机侧栏：钉住不复制内容，取消钉住对拥有者无影响；拥有者删除或归档后，该行仍在并标注状态，可取消钉住。
- 电脑不在时记录类写照常：改名、归档、调整顺序、编辑 Base 行、写 App 记录都会成功，等它醒来后对账。执行类动作——发送、停止、批准、回答、插话、删除 Chat——就地置灰并说明原因、保留草稿，电脑回来后自行恢复。
- Bottega 保留一个服务端总开关，必要时可为所有人关闭远程操作。关闭期间，浏览器里的 Chat 为只读；阅读转录和实时观看运行中的轮次仍然可用。

## 本地存储与 Bottega 文件夹

- Chat、Base、Project、App 与附件保持持久的本机所有权，并具有中断恢复与明确的留存规则。
- 可读内容集中在首次设置选择的 Bottega 文件夹：Chat 转录、原始附件、保存的产物、Chat Home 文件、Project 信息、Base 记录、App 源码与 Skills；账号设置、加密密钥、设备授权与执行记录留在各自电脑的应用数据目录。
- 备份方式是退出 Bottega 后复制整个文件夹；运行中复制只能作为尽力恢复的来源，并会报告缺口。不支持 iCloud Drive、Dropbox 等网盘同步目录。
- 本机 Chat 数据库无法打开时，可在保留旧数据库的前提下从文件夹重建对话。
- 在 设置 › 通用 里移动文件夹（包括移到另一块磁盘），所有保存的路径随之更新；也可以清空这台电脑上 Bottega 的全部数据，云端数据仍保留在账号里。
- Bottega 文件夹属于发布它的那台电脑：同一台电脑在重装、清数据或换 profile 后零操作接管，另一台电脑被指名拒绝；从未同步过的文件夹在任何电脑上都能打开。
- 更换版本前备份 Bottega 文件夹与完整应用数据目录。0.2.0 保留已有云端内容，要求协议 14；见[升级说明](../getting-started/README.zh-CN.md#升级到-020)，从更早版本升级时也请阅读对应的历史迁移说明。

## 随包运行时与 Agent 边界

- Bottega 自己的工具——内置 MCP server、App 界面编译器、Agent 适配器以及 App 的 Node 脚本——运行在应用内置的 Node 24 上，从不使用 PATH 里的 Node。使用 npm、pnpm 或 yarn 的 App 命令，以及你用 npx 启动的 MCP server，仍然使用你自己的 Node。
- 每个 Agent 回合都读不到 GitHub CLI 的配置目录；各 Agent CLI 自己的登录不受影响。
- 评审计划时永远不会提升 Agent 的权限；浏览器工具只读取本 Chat 的标签页和你选中的那一个。
- 拒绝把 Bottega 文件夹放在不安全的位置，例如用户主目录或卷的根目录。

## 共同基础

这些能力域遵守同一组原则：本机 CLI 凭据主权、capability 有界文件访问、主进程持久化所有权、显式归档与删除流程，以及后端不支持某项能力时的诚实降级。
