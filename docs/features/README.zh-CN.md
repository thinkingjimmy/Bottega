# Bottega 功能

[文档首页](../README.zh-CN.md) · [English](./README.md)

Bottega 把 Agent 对话视为一个可持续、本地工作空间的控制面。产品由以下核心能力域构成。

本文描述 **0.4.4／协议 27** 的源码能力。安装包可用性与实际验收范围以[最新稳定 Release](https://github.com/thinkingjimmy/Bottega/releases/latest)为准。

## Multi-agent

- Codex 通过原生 App Server 连接；Claude Code、Kimi Code 与 OpenCode 使用现有的本地 CLI 连接方式。普通 Codex Chat 按实际原生协议和所需能力准入，不要求单一 CLI 版本；原生标题生成与隔离编辑保留独立 CLI 资格要求。聊天布局保持不变。
- 聊天空闲时可为下一轮切换 Agent，保留同一转录、每条回复的作者及有界历史接续；各家官方 CLI 继续管理自己的登录、用量与配额。
- 输入框展示运行时与认证可用性，并提供有作用域的安装、登录和重试入口。
- 在设置页和 Agent 选择器查看 Codex、Claude Code、Kimi 与 OpenCode Go 可获得的配额窗口、剩余额度与重置时间。Codex 额度读取与可选更新提示独立于普通 Chat 的版本准入；无法读取时不编造额度。
- 在 设置 › 通用 › 标题生成 中选择支持标题的 Agent 与模型。具备资格的 Codex 标题使用所选模型，在独立的临时只读任务中执行，不带工具和工作区指令。标题执行不可用时，保留所选 Agent 与模型并使用首条消息，不自动切换 Provider。
- 提供 Plan、运行中 Steer、消息队列与可见的工具过程，同时保留后端能力差异。运行环境恢复后，排队的首条消息继续发送；长历史分批加载并保留阅读位置，代码高亮由共享 Worker 执行。
- 创建 Section 与 Provider 原生子代理并行工作，查看进度，在明确预算内交接上下文，并把有价值的结果提升为持久 Section。Provider 设置与普通 Chat 分叉继续可用。
- 搜索和接续受支持的本机 CLI 历史，不静默改写原始记录。
- 在设置中手动导入 Project 历史，仅包含已安装的 Agent；重新打开 Project 不再扫描。
- 导入的历史在任何档案中都能用普通输入框继续，Project 是否已绑定目录都不影响；转录里只有一条分隔线标出导入历史的结束点。

### Codex 命令权限

Codex 使用自身的沙箱与审批。**逐项询问**将额外命令权限请求交给你；**代我批准**交给 Codex 自动审核，审核可以批准，也可以拒绝。拒绝后不会把聊天切换为完全访问。

这两种模式都允许联网和工作区外的普通读取。写入范围包括工作区、明确增加的目录和临时目录；获批操作可以获得额外访问权限。**完全访问**取消工作区沙箱，不再询问边界审批。操作系统和管理策略仍可限制操作。

Bottega 不再为 Codex 命令添加原有的凭据路径拒读、内部路径保护或只读子树，包括 GitHub CLI 配置目录。这些文件可能被读取，获批操作或完全访问可能修改它们。工具授权和关闭 Skills 不会为命令建立另一层文件系统隔离。

Plan 沿用所选权限模式，不表示文件系统只读。普通 Codex Chat 不提供通用的严格只读、禁止联网、禁止工具或 Skills 文件隔离角色。具备资格的标题生成与隔离编辑使用各自的专用受限执行。其他不支持的要求会在执行前说明，不静默放宽限制，也不把固定使用 Codex 的任务交给其他 Provider。

命令输出保留在原命令详情中。后台服务在 Chat 输入框上方显示命令名称、状态与独立停止按钮。停止失败时保留重试入口，其他服务继续运行。Bottega 继续检查工具授权、Chat 归属和进程生命周期。

## 草图

- 通过输入框 **+ → 草图** 绘画、添加文字或八种图形，并局部擦除笔迹或图形。
- 自适应方形画布提供浮动工具、撤销/重做、颜色与粗细控制。
- 从草稿或还原队列中重新打开草图继续编辑，发送时通过普通图片附件流程交付白底 PNG。
- 草图作为内置插件管理，可通过 Agent 对话修改副本、切换已保存的版本。构建失败时保留原可用版本，已确认的草图源内容可在重启后恢复。

## 产物

- 在专用编辑器中打开原生 Canvas v3、Slides v4、Design System 和 Dashboard。Dashboard 使用固定 CSV、TSV 或 JSON 数据。作品页面与组件示例保持隔离，不能获得宿主写入权限。
- 在第三栏标签中同时打开多个作品和其他预览，再次打开时激活已有标签。切换或关闭前等待保存；失败时保留当前标签与未发送输入。
- 将元素、区域或整件作品的指令加入原 Chat 草稿，保留文字和附件，按普通发送流程提交。已发送意见保留准确指令和目标版本，应用结果在同一 Chat 链接到保存版本。
- 使用具有独立 CLI 资格要求的隔离编辑，并明确确认结果。保存结果未知时恢复原操作，不再调用模型；不支持的执行路径说明原因并保持不可用。
- 浏览固定只读 History 预览、作者与变化。恢复选定改动或完整版本，保留其他当前作品；暂停的恢复沿原操作继续。
- 将源码、资源、意见和完整受支持历史导出为项目 ZIP。在固定原工具中打开，或导入新的 Bottega 工作区，以新权限继续编辑。
- 无需打开编辑器即可使用独立 dataviz 指导与配色校验，保留原规则的警告与失败。
- 退役格式的文件与快照保持原样。不支持的卡片不会打开编辑器或恢复写入权限。
- Agent 可视化可在转录内联显示、展开或在侧栏打开。产出文件可预览、保存、在文件夹中显示或快速查看；工作表导入 Base 需明确确认行合并。
- Claude artifact 在内置浏览器中打开，复用持久分区。隔离预览不获得宿主写入能力；无效或超限输入说明原因。
- 拥有者电脑发布所需字节后，可在其他设备读取同步作品。加密浏览器视图保留未发送输入和明确的冲突选择。

## Base

- 让 Chat 或 Project 在对话旁拥有结构化、以 row 为事实源的数据空间。
- 同一份数据支持 Table、List、Kanban、Map、Chart 与 Gallery 六种视图。
- 支持公式、relation、筛选、排序、附件、行历史，以及 CSV/JSON/XLSX 交换。
- Agent 通过显式内置工具与 revision 校验读取和修改 Base。
- App 写入受 capability 约束，GUI 不会静默获得无限制数据权限。
- 原 Workflow 的阶段与验收标准列现在是普通可编辑字段，保留原 ID、选项、值与视图引用。

## 插件

- 在同一目录中浏览官方功能、已有 App、个人插件和外部 Host Package，查看能力、依赖、来源与运行状态。外部适配器保留原有设置与数据归属。
- 一个包可以组合页面、Widget、输入扩展、工具、服务和 Chat 模式。普通使用不会创建源码 Project；首次创作才建立或复用 Library Project，多个 Chat 可以在同一源码中工作。
- 使用随包 Node 与 pnpm 安装依赖。依赖安装脚本默认关闭，确有需要时明确确认。构建通过校验后本机实例自动更新，失败时保留可用代码。恢复代码版本不回退当前数据。
- Chat 模式在首条消息前选择，发送后保持固定；Agent 与模型选择保留原有行为。
- 在插件详情中展开工具，查看完整说明、输入输出字段和原始 JSON 定义。接收电脑需审查并接受账号内的加密包，才可使用。
- 后台插件运行受信任的本机代码，可以使用宿主凭据。插件开关控制 Bottega 提供的能力，不会停用 Provider 自带的原生工具。任意原生模块和远程脚本不在通用兼容范围内。
- 关闭插件保留内容与设置。缺少依赖时暂停受影响的能力，并说明原因。代码恢复、插件移除与数据删除继续由各自原有流程处理。
- 本版本未开放第三方 Provider 模块，生产环境仍提供四个内置 Provider；不包含公开插件市场或 SDK 发行。

## App

- 可编辑 App 因构建校验问题被隔离时，选择「从源码重新构建」，确认权限后再打开。
- 从不可变 Git revision 安装 static、server 或 Base-backed App。
- 随包的记账与健身 App 使用 React 界面与共享交互规范。
- 安装、重建、授权与激活前检查 App 的最低 Bottega 版本，升级后返回原候选继续确认；两个随包 App 均要求 Bottega 0.1.3 或更新版本。
- App 改名保留当前运行版本、数据与授权，无需重新构建。
- 可从桌面或 Web 关闭、重新打开 App。关闭前说明将停止的运行工作，保留排队任务，Base 数据仍可编辑；破坏性操作单独确认。
- 使用随包交付的 Fitness Log 浏览 17 个肌肉区域的 72 个动作、查看动作动图并管理训练计划，宿主 React 界面支持五语言。
- 通过 App SDK 读取完整、版本一致的 Base 快照，并获得可恢复的加载状态和显式重试入口。
- 把 App 绑定到 Chat 与 Project，同时分离使用、编辑和授权。
- 通过受约束的产品 SDK，在结构化数据旁呈现 App GUI。
- 针对精确 App generation，分别授权 read、insert、patch、delete 与 attachment 能力。

## 工具与 Extension

- Settings › Tools 提供全局默认值，并允许针对一个精确 Project 覆盖内置工具与手动 MCP server。
- turn 开始前冻结最终工具与 MCP plan，重试和 session 恢复不会静默采用更新后的权限。
- Extension 可安装到全局或一个精确 Project；Skill、App requirement、session、retained data 与删除清理共用同一 scoped owner。
- MCP 密钥只进入 main-owned sealed storage；持久化所有权证据不完整时一律 fail closed。

## Memory

- 长期 Memory 默认关闭，召回或采集前必须获得明确同意。
- 可选择产品托管的本机 OpenViking 或 EverOS 后端。
- Memory 插件入口与 Long-term Memory 正文中的服务授权独立控制；关闭插件保留服务选择与数据。
- 召回范围可以限定为单个 Chat、一个 Project group，或个人工作空间。
- 在把上下文交给 Agent 前，严格分离可信产品指令与不可信召回事实。
- 明确显示交付、重建、来源、版本与注意状态，不把“不可用”伪装成“空”。
- 可在 Web 设置中暂停或恢复某台电脑的 Memory；离线请求保持待执行，直到该电脑实际应用。
- 记忆库保存在本机，但提取内容可能调用你配置的模型服务并产生费用。回填既有历史需要独立同意；普通采集暂停后，已单独授权的重建仍可能继续。

## 后台活动

- 后台运行由一个开关管理，登录自启可单独设置，两项默认关闭。
- 在「设置 › 通用」中显示或隐藏菜单栏图标。后台任务和 Dock 分别设置。
- 在 Bottega Dock 添加「任务」组件，关注运行中的工作与待处理请求，使用键盘导航并返回对应 Chat。隐私模式隐藏任务内容与数量。
- 通过可用的后台入口重新打开或退出 Bottega。
- 从侧栏下载更新，无需离开当前页面。侧栏与设置显示相同的进度和百分比。下载完成后，由你选择「重启并更新」；工作区空闲不会触发重启。

## Bottega Dock

受控版本检查在 macOS 27 Apple 芯片电脑上覆盖 macOS 26.4.1 和 27.0.0。物理 macOS 26、准确签名包的 Dock 替代、批准、恢复、登录／重启与显示器组合仍需单独验收。

- 从可用 Bottega App 的菜单固定到 Dock，点击后在独立窗口打开或聚焦，保留会话与草稿。Dock 与侧栏固定互相独立；拖动排序，拖出取消固定，菜单在所选图标旁展开。

**macOS 26 或 27 · Apple 芯片**

- 在 macOS 26.x 或 27.x 的 Apple 芯片电脑上，把你在 Bottega 里做的 App、其他应用、访达、下载、废纸篓与每个 Agent 的 AI 额度环放进同一条程序坞。此要求适用于整个 Dock 插件；主应用的系统要求不变。
- 在 设置 › 插件 › Dock 中开启。可选择共存模式；已安装的主程序、原生辅助程序、恢复程序和随包后台服务配置通过验证后，可选择替代模式。开发版和未签名包提供共存模式。
- 确认替代后，Bottega Dock 按系统 Dock 的固定 App 列表和顺序调整布局，保留 Bottega App 快捷方式、小组件和系统入口。共存模式仍可手动复制。
- 后台项需要批准时，从 Dock 设置打开系统设置。返回后只刷新状态，不自动注册或接管。macOS 找不到恢复服务的注册记录时，该记录可能尚未创建。确认替代模式后，可在安装验证通过、待恢复事项处理完成时，点击「继续启用」重试注册。
- 恢复程序握手、Dock 入口和偏好写入确认后，才显示替代已生效。原生桥接程序在准备或接管期间意外退出时，会启动系统程序坞恢复并暂停替代，直到用户明确选择继续。恢复失败保留记录和「重试」入口。独立恢复程序会在短暂等待后再次检查中断的恢复，避免一直跳过未完成的恢复记录。
- 可使用主屏、优先外接屏或指定显示器，并停靠在左侧、底部或右侧；显示器和边缘偏好仅保存在这台电脑上。
- 支持时使用原生玻璃外观，不可用时回退到稳定背景；关闭插件保留布局。
- 同一账号的每台电脑使用同一份端到端加密的 Dock 布局；同时修改会自动合并，真正的冲突会询问你。

- 新 Dock 设置默认常显，也可选择自动隐藏。App 与 Widget、其他运行中 App，以及下载与废纸篓分组显示。
- 即使隐藏其他运行中 App，也可通过 Dock 中的 Bottega 图标返回。退出原生 App 时保留正常的保存与取消提示。
- 按时间浏览下载内容，显示原生缩略图与文件图标。可放大预览、按 Escape 返回，或在 Finder 中显示文件；隐私遮罩同时隐藏缩略图。

### 自定义 Widget

启用 Dock 后，可在 App › 小组件中添加、设置或创建小组件。创建后可在插件源码 Project 中继续编辑。预览保留为可选入口。本机构建通过校验后，已安装实例自动更新；失败时保留可用版本。每个实例独立保存设置与 Base／API 许可，API 凭据在本机加密保存。支持标准或隔离详情、已授权动作与手动刷新。明确分享后才开启账号内交付；收到编译包不会自动获得执行或读取本地数据的权限。

### 天气

天气已预装，可从 App › 小组件或 Dock 的添加菜单加入。搜索城市，再按地区或国家选择结果。每个小组件独立保存所选城市。小号显示当前天气，中号增加今日最高和最低温度，大号增加未来三天预报。原本使用自动定位的小组件会提示选择城市。无需 Agent、账号或 API Key。可以手动刷新，小组件可见时也会每 15 分钟刷新。读取失败时，小组件保留该城市上次成功读取的数据，并标明已过期。

## Cloud Sync

- 同步始终可选：不登录也能完整使用，首次设置里不会提到账号；登录本身不上传任何内容，直到你确认第一次同步。
- 通过系统默认浏览器完成 Google 登录，在浏览器里选中那台电脑上 Bottega 显示的验证码来批准请求，桌面应用再接续会话；Bottega 不会索取该密码。
- 用独立的同步密码解锁已同步内容。新设定的密码至少 12 个字符，包含字母与数字，至少 5 个不同字符，不能以大段重复或连续字符为主，不能包含邮箱名、`bottega` 或最常见的密码；表单会随输入逐条打勾。内容密钥在你自己的设备上用 Argon2id 派生，内容在上传前用 XChaCha20-Poly1305 封装。
- 明确接受没有找回：没有恢复密钥、没有其他设备批准、没有密码重置，也没有重置同步；仍持有加密密钥的设备可以继续解密已有内容。创建加密空间前会说明该风险并要求确认。
- 一个账号一个加密空间。第一台电脑设定同步密码，之后的每台电脑、浏览器与手机输入它；只有桌面能设定。
- 设置的同步一栏只有三件事：登录状态、本机显示名、退出登录。退出登录只停止发布与接受命令，不删除任何内容；清除这台电脑的云端副本是另一个动作，删除账号又是另一个。
- 首次上传诚实可见：同步行按真实上传字节计数，且小的对话先传，几秒内数字就开始走。
- 同步 Chat 及其工具过程、Subagent 与附件，Base 及其 App 记录，Project 元数据与 Skills。冲突的修改保留双方候选并交由显式决定，不静默覆盖。
- 离线或暂停时继续工作：本机内容保持可读，排队任务按同一身份恢复；密码错误或网络中断都不会删除本地数据或云端密钥。

## Cloud Web 与远程操作

- 在 [app.getbottega.app](https://app.getbottega.app) 的浏览器中阅读 Chat，转录、工具过程、Subagent 与附件与桌面一致。
- 搜索聊天标题及最近 7 天的消息正文。搜索在浏览器中针对解密后的内容运行，查询词与明文索引不上传。
- 使用同样的六种 Base 视图，读取和编辑已同步的 App 记录，恢复或删除归档项目，并管理设备、会话与偏好。
- 需要电脑确认的插件请求仍由该电脑处理。
- 可在信任的浏览器上保持解锁，也可随时重新锁定。静态与 Base 型 App 的界面也能在浏览器里打开；server 型 App 的界面、应用内浏览器和本机工具仍属于各自的电脑。
- 支持手机浏览器：768px 以下的布局、触控目标、抽屉与拖拽交互自适应；App 与 Base 菜单适应窄屏，离线状态在受影响的操作旁显示。
- 浏览器支持时可选择开启通知；实际送达取决于浏览器、系统权限与设备状态。
- 同步未连接时，远程输入区说明如何在电脑上登录并完成同步。
- 登录即远程操作：一台登录的电脑把自己的 Project 与 Chat 发布到账号并接受命令，产品里没有第二个开关。
- 用侧栏顶部的电脑切换器切换电脑，Cloud Web、手机与桌面共用同一个组件。账号里出现第二台电脑后才显示，标签带在线状态，桌面把自己排在第一位；切换器下方的侧栏属于被选中的那台电脑。
- 在设置里给本机改名；与其他电脑重名会被拒绝，新电脑注册时撞名会自动加数字后缀。
- 被选中的电脑醒着时即可操作：发送消息、查看实时输出、停止、批准或拒绝权限请求、回答追问、插话与追加消息。目标必须在线、已解锁且协议版本一致。
- 多个设备可以操作同一条 Chat：消息按到达顺序排队，重复的停止只算一次，对同一个权限请求的第二次回答显示一行「已在 *电脑* 处理」而不是错误。
- 使用另一台电脑的 Project：它带地球角标与归属电脑名，不提供目录与路径，在它下面新建的 Chat 在那台电脑上创建、执行与存储。桌面可以把它钉进本机侧栏：钉住不复制内容，取消钉住对拥有者无影响；拥有者删除或归档后，该行仍在并标注状态，可取消钉住。
- 电脑不在时记录类写照常：改名、归档、调整顺序、编辑 Base 行、写 App 记录都会成功，等它醒来后对账。执行类动作——发送、停止、批准、回答、插话、删除 Chat——就地置灰并说明原因、保留草稿，电脑回来后自行恢复。
- Bottega 保留一个服务端总开关，必要时可为所有人关闭远程操作。关闭期间，浏览器里的 Chat 为只读；阅读转录和实时观看运行中的轮次仍然可用。

## 本地存储与 Bottega 文件夹

- Chat、Base、Project、App 与附件保持持久的本机所有权，并具有中断恢复与明确的留存规则。
- 可读内容集中在首次设置选择的 Bottega 文件夹：Chat 转录、原始附件、保存的产物、Chat Home 文件、Project 信息、Base 记录、App 源码与 Skills；账号设置、加密密钥、设备授权与执行记录留在各自电脑的应用数据目录。
- 备份方式是退出 Bottega 后复制整个文件夹；运行中复制只能作为尽力恢复的来源，并会报告缺口。不支持 iCloud Drive、Dropbox 等网盘同步目录。
- 本机 Chat 数据库无法打开时，可在保留旧数据库的前提下从文件夹重建对话。
- 在 设置 › 通用 里移动文件夹（包括移到另一块磁盘），所有保存的路径随之更新；也可以清空这台电脑上 Bottega 的全部数据，云端数据仍保留在账号里。
- Bottega 文件夹属于发布它的那台电脑：同一台电脑在重装、清数据或换 profile 后零操作接管，另一台电脑被指名拒绝；从未同步过的文件夹在任何电脑上都能打开。
- 更换版本前备份 Bottega 文件夹与完整应用数据目录。0.4.2 使用协议 27，移除 Workflow、独立 Agent 配置与 Bottega Team。请阅读[移除范围与升级说明](../getting-started/README.zh-CN.md#升级到-042)，确认发布维护将删除哪些数据。

## 随包运行时与 Agent 边界

- Bottega 自己的工具——内置 MCP server、App 界面编译器、Agent 适配器以及 App 的 Node 脚本——运行在应用内置的 Node 24 上，从不使用 PATH 里的 Node。使用 npm、pnpm 或 yarn 的 App 命令，以及你用 npx 启动的 MCP server，仍然使用你自己的 Node。
- 插件依赖安装与构建使用随包 Node 和 pnpm，不要求 PATH 中有包管理器。这不改变外部 App 命令或 MCP server 使用的 Node。
- 各 Agent CLI 继续管理自己的登录。Codex 命令权限可能允许访问本地凭据文件，包括 GitHub CLI 配置目录；见 [Codex 命令权限](#codex-命令权限)。
- 评审计划不会改变所选执行模式；Codex 仍可按该模式申请额外命令权限。浏览器工具只读取本 Chat 的标签页和你选中的那一个。
- 拒绝把 Bottega 文件夹放在不安全的位置，例如用户主目录或卷的根目录。
